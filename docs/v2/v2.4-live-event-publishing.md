# V2.4 Live Event Publishing & Simulation Integration

> GM이 V2.3 Preview를 승인하면 실제 게임에 Breaking News → Event Engine → Economy Patch → WebSocket까지 자동 연결됩니다.

## Overview

V2.4는 V2.3 Real-world Intelligence의 GM Preview 결과를 **실제 시뮬레이션에 발행(Publish)**합니다.

```
V2.3 Preview (뉴스 → AI 분석 → 3 시나리오 → Economy Preview)
        ↓ GM Approve
V2.4 Publish (Breaking News → Custom Event → Economy Patch → WebSocket)
        ↓
CEO Dashboard / Ranking / Accounting (기존 P4 Event Engine)
```

**V1 RC는 수정하지 않습니다.** 기존 `EventEngineService.fireCustomFromDraft()` 경로를 그대로 사용합니다.

## Architecture

| Layer | Path | Role |
|-------|------|------|
| Publish Domain | `lib/v2/intelligence/publish-*` | Lifecycle, conflict, bridge, follow-up, debrief |
| Event Chain (V3 stub) | `lib/v2/intelligence/event-chain-types.ts` | 확장 가능 데이터 모델만 (실행 안 함) |
| API | `app/api/v2/intelligence/publish/*` | GM-authenticated publish workflow |
| UI | `components/v2/intelligence/PublishWorkflowPanel.tsx` | GM Publish UI |
| Bridge | `lib/v2/intelligence/publish-bridge.ts` | IntelligencePreview → EventScenarioDraft |
| Storage | `.bsp-data/v2-intelligence-publish.json` | Publish records, audit, timeline, event chains |

### V1 RC isolation

- V1 게임 규칙, step handler, accounting, settlement **변경 없음**
- V1 `/gm` 라우트에 AI 호출 **없음**
- 기존 P4 Event Engine **재사용** (`fireCustomFromDraft`)
- AI는 계산하지 않음 — 분석·설명·교육 코멘트만 제공
- 실제 Economy 계산은 `economy-engine.ts`가 수행

## Workflow

```
Draft
  ↓
AI Generated (initiatePublish)
  ↓
GM Review (markReviewed)
  ↓
GM Edit (optional)
  ↓
Approve
  ↓
Schedule (IMMEDIATE / NEXT_STEP / NEXT_HALF)
  ↓
Publish → Event Engine
  ↓
Economy Patch
  ↓
Breaking News (WebSocket news.published)
  ↓
Active
  ↓
Expiring / Expired (endEvent + debrief)
  ↓
Archived
```

모든 상태 변경은 `PublishAuditEntry` + `EventTimelineEntry`에 기록됩니다.

## Lifecycle

| Status | Description |
|--------|-------------|
| `GENERATED` | Preview에서 publish record 생성 |
| `REVIEWED` | GM 검토 완료 |
| `APPROVED` | GM 승인 |
| `SCHEDULED` | 발행 시점 예약 |
| `PUBLISHED` | Event Engine에 등록 (예약 대기) |
| `ACTIVE` | Economy Patch 적용 + Breaking News 발행 |
| `EXPIRING` | 만료 예정 |
| `EXPIRED` | endEvent 호출 + Debrief 생성 |
| `ARCHIVED` | 보관 |

## Scheduling

| Timing | Behavior |
|--------|----------|
| `IMMEDIATE` | 즉시 Breaking News + Economy Patch |
| `NEXT_STEP` | 다음 Step advance 시 발행 |
| `NEXT_HALF` | 다음 반기 시작 시 발행 |

예약 이벤트는 `.bsp-data/v2-drafts.json` + Event Engine scheduled state에 저장되어 **서버 재시작 후에도 유지**됩니다.

## Simulation Integration

Publish 시 기존 P4 파이프라인을 따릅니다:

```
Breaking News
  ↓
Custom Event (AI-{draftId})
  ↓
Economy Patch (applyEventPatch)
  ↓
Economy Snapshot
  ↓
Decision → Production → Sales → Accounting → Dashboard → Ranking
```

`publish-bridge.ts`가 IntelligencePreview를 `EventScenarioDraft`로 변환하고, `ScenarioStudioService.approveDraft()`가 Event Engine을 호출합니다.

## Breaking News

Publish와 동시에 CEO 화면에 실시간 Breaking News가 표시됩니다.

포함 항목:
- Headline, Summary, Category, Severity
- Published Time, Effective Time, Duration
- Display Mode (`HEADLINE_ONLY` / `DIRECTIONAL` / `DETAILED`)

WebSocket: `news.published` → `CeoNewsPanel` (`components/v2/news/CeoNewsPanel.tsx`)

## Global Notification

WebSocket (`/api/v1/ws`)으로 모든 CEO 화면에 동시 전달:

| Event | Purpose |
|-------|---------|
| `news.published` | Breaking News 배너 |
| `economy.changed` | Environment Badge |
| `event.fired` | Active Event |
| `dashboard.updated` | KPI Refresh |

## Acknowledgement

- CEO: `/api/v2/news/[newsId]/acknowledge` — 뉴스 읽음 표시
- GM: `/api/v2/intelligence/publish/[id]/ack` — 팀별 읽음 여부
- 읽지 않아도 게임 진행은 멈추지 않음

## Conflict Resolution

`conflict-resolver.ts`가 동시 활성 이벤트의 Patch 충돌을 검증합니다.

- 동일 Economy 변수에 다중 이벤트 영향 시 STACK/CLAMP/OVERRIDE 판단
- `CRITICAL` 충돌 시 `canProceed: false` → GM Preview 확인 필요
- API: `GET /api/v2/intelligence/publish/[id]/conflicts`

## Event Timeline

GM은 시간순으로 이벤트 생명주기를 확인합니다.

- 생성 → 검토 → 승인 → 예약 → 발행 → 활성화 → 만료 → Archive
- API: `GET /api/v2/intelligence/publish/[id]/timeline`
- Replay 기록 포함

## AI Consultant Follow-up

발행 후 GM 전용 추가 코멘트:

- 학생 행동 예측 (예: "차입 증가를 먼저 선택할 가능성")
- 토론 유도 가이드
- `gmOnly: true` — 학생에게 공개하지 않음

API: `POST /api/v2/intelligence/publish/[id]/followup`

## Educational Debrief

이벤트 만료 시 자동/수동 Debrief 생성:

- 학생들의 주요 선택, 가장 많이 선택한 전략
- 좋은 선택 / 아쉬운 선택
- 다음 토론 질문

API: `POST /api/v2/intelligence/publish/[id]/debrief`

## Replay

GM은 동일 뉴스 Preview를 다른 시나리오로 Replay할 수 있습니다.

```
동일 Event → 다른 선택 (pessimistic/neutral/optimistic) → 결과 비교
```

API: `POST /api/v2/intelligence/publish/[id]/replay`

## Event Chain (V3 준비)

`event-chain-types.ts` — 데이터 모델만 준비, V2.4에서 실행하지 않음.

```
관세 인상 → 공급망 차질 → 원가 상승 → 가격 인상 → 수요 감소 → 현금 부족 → 금리 인상
```

Publish 시 root node stub이 생성되며, V3에서 chain execution을 연결할 수 있습니다.

## Performance

목표: 100팀 동시 Publish 1초 이내 전파

- WebSocket broadcast는 session-scoped fan-out
- Economy Patch는 session-level (팀별 중복 계산 없음)
- Idempotency key로 중복 publish 방지

## API Design

All routes require GM session auth (`requireGmSession`).

| Method | Endpoint | Purpose |
|--------|----------|---------|
| GET | `/api/v2/intelligence/publish?sessionId=` | List publish records |
| POST | `/api/v2/intelligence/publish` | Initiate or full publish |
| GET | `/api/v2/intelligence/publish/[id]` | Get record |
| POST | `/api/v2/intelligence/publish/[id]/review` | Mark reviewed |
| POST | `/api/v2/intelligence/publish/[id]/approve` | Approve |
| POST | `/api/v2/intelligence/publish/[id]/schedule` | Schedule timing |
| GET | `/api/v2/intelligence/publish/[id]/conflicts` | Conflict preview |
| GET | `/api/v2/intelligence/publish/[id]/timeline` | Event timeline |
| GET | `/api/v2/intelligence/publish/[id]/ack` | Acknowledgement summary |
| POST | `/api/v2/intelligence/publish/[id]/followup` | Generate follow-up |
| POST | `/api/v2/intelligence/publish/[id]/debrief` | Generate debrief |
| POST | `/api/v2/intelligence/publish/[id]/replay` | Replay with different scenario |
| POST | `/api/v2/intelligence/publish/[id]/lifecycle` | Expire or archive |

## Known Issues

- Intelligence publish audit는 V1 GM audit log와 별도 store (cross-link 미구현)
- `NEWS_PUBLISHED` GM audit action은 타입만 정의, V1 audit log에 미기록
- Event Chain은 stub만 — V3에서 execution 구현 예정
- PostgreSQL persistence for V2 stores deferred (file JSON)
- GM auth deep-link from `/gm` → `/event-studio/intelligence` deferred
