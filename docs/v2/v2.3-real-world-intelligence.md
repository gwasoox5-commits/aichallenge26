# V2.3 Real-world Intelligence & AI Management Consultant

> GM Preview + V2.4 Publish — V2.4 connects Approve → Publish → Event → Economy → WebSocket.

## Overview

V2.3 extends V2.1a Event Scenario Studio with a **real-news-driven pipeline**:

```
Real News Search → AI Analysis → 3 Scenarios → Economy Mapping → GM Preview
                                                      ↓
                                            AI Management Consultant (GM-only)
```

V2.4 connects: **Approve → Publish → Event → Economy → WebSocket** ([V2.4 doc](./v2.4-live-event-publishing.md)).

## Architecture

| Layer | Path | Role |
|-------|------|------|
| Domain | `lib/v2/intelligence/*` | Types, adapters, AI, scoring, stores |
| API | `app/api/v2/intelligence/*` | GM-authenticated REST endpoints |
| UI | `components/v2/intelligence/*` | Korean GM Preview workflow |
| Route | `/event-studio/intelligence` | V2.3 sub-route (V2.1a intact at `/event-studio`) |

### V1 RC isolation

- No changes to V1 game logic, event auto-fire, economy patch auto-apply, or CEO WebSocket flows.
- V2.3 `buildPublishIntent()` returns a V2.4 hook object only — **never executes publish**.

## News Flow

1. GM enters keywords (AI, 반도체, 관세, 환율, ESG, supply chain, …).
2. **News adapter** searches via pluggable provider.
3. Results show: title, summary, source, published date, URL.
4. GM selects article(s) → pipeline continues.

### Source Strategy (Pluggable Adapter)

| Provider | Env | Behavior |
|----------|-----|----------|
| `fixture` (default) | `BSP_NEWS_PROVIDER=fixture` | Keyword search over `tests/fixtures/v2/news-articles.fixture.json` |
| `gnews` | `BSP_GNEWS_API_KEY` + `BSP_NEWS_PROVIDER=gnews` | GNews API with **graceful degradation** to fixture on failure |

CI/tests **never require live external APIs**.

## OpenAI Prompt (Responses API)

Pattern matches V2.1a `openai-generator.ts`:

- **Analysis**: event summary, key issues, supply/production/sales/financial impacts, risks, opportunities.
- **Scenarios**: pessimistic / neutral / optimistic with assumptions, variable impacts, expected outcomes.
- **Consultant**: GM-only briefing (risks, CEO priorities, student mistakes, discussion/debrief questions).

When `BSP_OPENAI_API_KEY` is unset → fixture JSON under `tests/fixtures/v2/`.

## Prompt Version

Stored on all AI outputs as `promptVersion`:

| Version | Notes |
|---------|-------|
| `v1.0` | Initial analysis + scenario prompts |
| `v1.1` | Citations, explainability, GM consultant (current default) |

Registry: `lib/v2/intelligence/prompt-registry.ts`

## Scenario Quality

`quality-scorer.ts` evaluates:

- realism, logic, economic consistency, education value, diversity, game fit

Overall score &lt; 55 → `recommendRegenerate: true` + Korean notes.

## AI Management Consultant

Generated in `consultant-generator.ts`. Fields include:

- Core risks / opportunities
- Most affected division
- Production, supply chain, financial, cashflow impact
- CEO review priorities
- Common student mistakes
- Instructor discussion + debrief questions
- Learning objectives + educational commentary

**`gmOnly: true`** — not exposed to students.

## Educational Commentary

Korean instructor comments and discussion questions are included in consultant output and surfaced in `ConsultantPanel` (GM UI only).

## Explainability

Per economy variable (`VariableImpactExplainability`):

| Field | Description |
|-------|-------------|
| `reason` | AI rationale |
| `confidence` | LOW / MEDIUM / HIGH |
| `assumption` | Underlying assumption |
| `proposedValue` / `clampedValue` | AI proposal vs bounded final |
| `lowAccuracyWarning` | `"추정 정확도가 낮음"` when LOW |

## Economy Mapping

Wraps V2.1a `variable-mapper.ts` + `bounds-preview.ts`:

- 14 studio variables → engine keys
- `STUDIO_VARIABLE_BOUNDS` clamp before preview
- GM sees: AI proposed, allowed range, final clamped value

## Scenario Library

Storage: `.bsp-data/v2-intelligence-library.json` (memory when `BSP_USE_MEMORY=1`)

Operations: **Save**, **Favorite**, **Duplicate**, **Export JSON**, **Import JSON**

## API Design

All routes require GM session auth (`requireGmSession`).

| Method | Endpoint | Purpose |
|--------|----------|---------|
| POST | `/api/v2/intelligence/news/search` | Keyword news search |
| POST | `/api/v2/intelligence/analyze` | Create preview + analyze articles |
| POST | `/api/v2/intelligence/scenarios` | Generate 3 scenarios |
| POST | `/api/v2/intelligence/preview` | Full preview + economy + V2.4 intent |
| GET | `/api/v2/intelligence/library?sessionId=` | List library |
| POST | `/api/v2/intelligence/library` | Save preview to library |
| GET/PATCH/DELETE | `/api/v2/intelligence/library/[id]` | Get / favorite / duplicate / delete |
| GET | `/api/v2/intelligence/library/export/[id]` | Export JSON |
| POST | `/api/v2/intelligence/library/import` | Import JSON |

## Manual Test — GM Preview Flow

1. Start app: `npm run dev`
2. Open `/event-studio/intelligence`
3. Enter session ID (use active GM session or `demo-intelligence-session` with GM token in localStorage)
4. Search keywords e.g. `반도체, 관세`
5. Select 1+ articles → **AI 분석 → 시나리오 → Preview**
6. Review: analysis → 3 scenarios → economy table → quality badge → consultant panel
7. **라이브러리 저장** / export JSON
8. Confirm: no changes on `/gm` economy, no CEO news

Without GM token: UI falls back to **client fixture demo mode** automatically.
