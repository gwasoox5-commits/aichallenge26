## 6. Transaction / Atomic Publish

**Approve pipeline** (`ScenarioStudioService.approveDraft`):

1. Validate draft state + session (block settlement immediate apply)
2. Map studio effects → engine effects + bounds preview
3. Create unpublished `NewsPublication` record
4. `EventEngineService.fireCustomFromDraft()` — P4 patch pipeline
5. On `IMMEDIATE`: set `publishedAt`, save news, `notifyNewsPublished()`
6. On `NEXT_STEP` / `NEXT_HALF`: register pending news; publish when event activates via `GameEngine.processStudioNewsPublications()`
7. On failure: rollback unpublished news record

**Idempotency**: `Idempotency-Key` header on approve → returns cached `ApproveResult`.

## 13. Known Issues

1. **PostgreSQL persistence**: Drafts use file JSON in MVP; PG model deferred to V2.2.
2. **Scheduled news timing**: Pending news publishes when P4 event becomes ACTIVE (step/half advance), not at intermediate step boundaries like "current step end".
3. **GM auth on `/event-studio`**: Requires manual sessionId + GM token from `/gm` login; no deep-link auto-session yet (V2.1c).
4. **OpenAI live errors**: Invalid API key throws `ERR_STUDIO_AI`; tests use fixture only.
5. **Duplicate active AI events**: Same draft re-approve blocked; different drafts with overlapping effects can stack (by design for multi-scenario debrief).
6. **Screenshot artifacts**: UI screenshots not captured in CI; manual verification via `/event-studio` and `/play`.
